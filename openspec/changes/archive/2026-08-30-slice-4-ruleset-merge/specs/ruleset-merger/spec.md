## ADDED Requirements

### Requirement: RuleSetMerger resolve function
The system SHALL provide a pure static function `RuleSetMerger.Resolve(RuleSetFile? community, RuleSetFile? generated, RuleSetFile? local) → EffectiveRuleSet` in FunkArr.Core that resolves the merge chain and returns the effective rules with per-rule provenance.

#### Scenario: Standalone layer (no overrides)
- **WHEN** only a community ruleset exists with no `Overrides` on any layer
- **THEN** `Resolve` SHALL return all community rules with `Layer = Community`

#### Scenario: Winner-takes-all without overrides
- **WHEN** community and local exist, local has no `Overrides`
- **THEN** `Resolve` SHALL return the local rules only (all with `Layer = Local`), matching current behavior

#### Scenario: Priority order: local > generated > community
- **WHEN** all three layers exist, none has `Overrides`
- **THEN** `Resolve` SHALL return the local rules (winner-takes-all for backward compat)

#### Scenario: Merge with Add
- **WHEN** local has `Overrides { Base = Community, Add = [rule-x] }` and community has rules [a, b]
- **THEN** `Resolve` SHALL return [a (Community), b (Community), rule-x (Local)]

#### Scenario: Merge with Replace
- **WHEN** local has `Overrides { Base = Community, Replace = [rule-a-modified] }` where rule-a-modified.Id matches rule "a" in community
- **THEN** `Resolve` SHALL return [rule-a-modified (Local), b (Community)]

#### Scenario: Merge with Remove
- **WHEN** local has `Overrides { Base = Community, Remove = ["a"] }` and community has rules [a, b]
- **THEN** `Resolve` SHALL return [b (Community)]

#### Scenario: Three-layer chain
- **WHEN** generated has `Overrides { Base = Community, Add = [gen-0] }` and local has `Overrides { Base = Generated, Replace = [gen-0-modified] }`
- **THEN** `Resolve` SHALL walk: local → generated → community, producing [community-rules (Community), gen-0-modified (Local)]

#### Scenario: Generated bypasses community
- **WHEN** generated has no `Overrides` (standalone) and local has `Overrides { Base = Generated }`
- **THEN** `Resolve` SHALL use generated as base, ignoring community entirely

#### Scenario: All layers null
- **WHEN** all three slots are null
- **THEN** `Resolve` SHALL return an empty `EffectiveRuleSet`

#### Scenario: Effective rules sorted by priority
- **WHEN** merge produces rules with priorities [10, 0, 5]
- **THEN** the returned rules SHALL be sorted by priority ascending [0, 5, 10]

### Requirement: EffectiveRuleSet result type
The system SHALL provide `EffectiveRuleSet` and `EffectiveRule` types in FunkArr.Core.

#### Scenario: EffectiveRule carries provenance
- **WHEN** a rule from the community layer appears in the resolved set
- **THEN** the `EffectiveRule` SHALL have `Rule` (the full rule) and `Layer = RuleSetLayer.Community`

#### Scenario: EffectiveRuleSet provides topic and channels
- **WHEN** resolving from a community base
- **THEN** `EffectiveRuleSet` SHALL carry `Topic`, `Channels`, and `Source` derived from the top layer

### Requirement: RuleSetMerger validation function
The system SHALL provide a pure static function `RuleSetMerger.Validate(OverrideConfig overrides, IReadOnlyList<Rule> baseRules) → IReadOnlyList<ValidationError>` that validates an override configuration against its resolved base.

#### Scenario: Replace ID must exist in base
- **WHEN** an override has `Replace = [{ Id = "nonexistent", ... }]` and base has no rule with that ID
- **THEN** `Validate` SHALL return an error "Replace rule 'nonexistent' not found in base"

#### Scenario: Add ID must NOT exist in base
- **WHEN** an override has `Add = [{ Id = "existing", ... }]` and base already has a rule with ID "existing"
- **THEN** `Validate` SHALL return an error "Add rule 'existing' already exists in base"

#### Scenario: Remove ID must exist in base
- **WHEN** an override has `Remove = ["nonexistent"]` and base has no rule with that ID
- **THEN** `Validate` SHALL return an error "Remove rule 'nonexistent' not found in base"

#### Scenario: No ID in multiple lists
- **WHEN** an override has `Replace = [{ Id = "x" }]` and `Remove = ["x"]`
- **THEN** `Validate` SHALL return an error "Rule 'x' appears in both Replace and Remove"

#### Scenario: Unique IDs within a document
- **WHEN** a rule set has two rules with Id = "dup"
- **THEN** `Validate` SHALL return an error "Duplicate rule ID 'dup'"

#### Scenario: No cycles in base chain
- **WHEN** a local layer has `Base = Generated` and generated has `Base = Local`
- **THEN** `Validate` SHALL return an error "Cycle detected in base chain"

#### Scenario: Valid override passes
- **WHEN** an override correctly references existing base IDs with no conflicts
- **THEN** `Validate` SHALL return an empty error list

### Requirement: ValidationError type
The system SHALL provide a `ValidationError` record with `string Message` and `string? RuleId`.

#### Scenario: Error structure
- **WHEN** a validation error is produced for rule "airdate"
- **THEN** the error SHALL have `RuleId = "airdate"` and a descriptive `Message`
